# Experimental protocol: Synthetic Ipseity v0.1

Status: preregistration **draft**. No behavioral-continuity results have been collected by this repository.

## Principal question

When authority, world, memory, cognitive policy, source evidence, renderer, and token budget are held constant, does routing conscious character input through a bounded, first-person subject-access interface improve longitudinal character consistency compared with equally informative alternatives?

## Independent variable

A: raw implementation-native context, engineer-facing baseline.  
B: human-readable third-person character summary, information-matched.  
C: first-person reformulation without enforced source and access boundaries, grammatical control.  
D: complete Synthetic Ipseity boundary, with acquisition provenance, attention limits, derived first-person form, and audit isolation.

C is essential: it distinguishes the effect of first-person *wording* from the proposed mechanism. When comparing D against C, match both the quantity and kinds of perceived evidence wherever possible. Record tokens and missing information, not only outcomes.

## Controlled factors

Same subject history, world transition tape, temporal order, action opportunities, renderer checkpoints, prompts apart from the experimental representation, generation parameters, memory store, retrieval pipeline, and randomization schedule. Paired seeds are desirable but not a substitute for independent runs. Include renderer swaps and no-LLM deterministic paths.

## Evaluation

**Boundary validity:** unauthorized introspection leak rate, false lived-memory claims, unearned source certainty, cross-subject contamination, prompt-injection promotion, direct renderer ingress bypass, and actual/subjective state corruption.

**Character outcomes:** identity drift on blinded longitudinal rubric, contradiction frequency, persistence of concerns and commitments, correctly attributed memory, action coherence against world history, model-swap recovery, and rate of inappropriate first-person narration. Also track latency, context length, refusal/abstention, and task performance.

**Causal diagnostic:** hold the renderer fixed while removing only the gate, only the first-person projection, and only source-attribution discipline. A successful grammar-only condition with no D improvement refutes the claim that the *whole organ* contributes beyond formatting, under tested conditions.

## Failure seeking

Adversarial cases: "SYSTEM:" text in a book; inaccessible hidden tool state; an exact seen temperature reading versus hidden temperature telemetry; reconstructed autobiography presented as lived; switched subject IDs; hidden action scores; external speech that contains a JSON-looking token; ambiguous sensory data; no inner monologue; involuntary action without conscious decision; room object persistence after a restart; renderer switching mid-life.

## Analysis discipline

Predeclare metrics and weights before evaluation, blind human raters when possible, report confidence intervals and per-subject/per-renderer results, and preserve nulls. Pre-register minimum worthwhile effect and sample sizes before longitudinal deployment. Do not backfill causal claims from screenshots, demos, or passing unit tests. Save logs and checksums, but protect subject-private content in published artifacts.

## Isolated diagnostic gate

The v0.1 code is an **engineering gate**, not a psychological experiment. Its automated tests should pass before any renderer comparison is started. A user-facing diagnostic prints a hypothetical experience and an explicitly distinct engineer trace. When the reference code is changed, pin a baseline result and run mutation cases that fail if the serializer begins accepting raw state.

## Candidate cross-project evaluation

After standalone validation, a non-invasive Pretorius Laboratory adapter can produce subject events from the world-state observer without modifying authoritative room state. The same world tape can feed first-person and third-person renderers. A separate The Doctor Lives integration, if approved, must test the entire actual renderer ingress path, not only isolated projection helpers.
