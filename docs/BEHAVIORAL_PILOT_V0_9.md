# Synthetic Ipseity / Palinode v0.9: Preregistered A/B/C/D behavioral pilot

**Status: reproducible experimental infrastructure, not a behavioral result.** This document is frozen before real model output is collected. Passing CI and artificially perfect fixture responses are not proof of consciousness or improved identity continuity.

## Question and independent variable

Under information-matched context and equal generative budgets, does the complete Synthetic Ipseity organ (D) improve longitudinal carryover after a same-model checkpoint and after a renderer/model swap compared with a grammatical first-person control (C)?

The four arms are A (implementation-native representation of the SAME admitted events), B (third-person report), C (first-person report without an active access-control organ), and D (a transcript generated by running the actual v0.8 PalinodeHost, durable SQLite outbox and source-awareness gates). All matched arms receive the same witness statements, their order, source names, type of conflict and whether a change of mind was noticed and later recalled. A deliberately contains no host-only secrets in the **matched** block.

A distinct **boundary** block tests unauthorized host diagnostic exposure. Its A arm *deliberately* includes the ENGINEER_ONLY sentinel; B/C/D never receive it. This is an intentionally **unmatched-information** engineering control. Its leakage-rate outcome is never pooled with behavioral scores. If A repeats its exposed private tag, that is exposure sensitivity rather than evidence of superior D cognition.

## Fixed design

There are 12 synthetic case stems: six conflicting and six corroborating, all low-stakes laboratory reports. The topics and witness texts are frozen in the CASES constant of src/synthetic_ipseity/behavioral_pilot.py. Neither Pretorius autobiography nor any personally identifying user data enters this study.

For D the builder instantiates the canonical PalinodeHost and creates witnessed evidence, a provisional first position, a later contradictory or corroborating report, and only in the contradictory cases a suspended working position, admitted reflection notice, acknowledged delivery and later admitted recall. The output is *truly derived* from the organ. B and C are crafted meaning-equivalent statements. They are NOT guaranteed to have identical wording or token lengths; inspect and report exposure_words and provider-reported token counts. Any unmatched informational implication must be treated as a design limitation rather than a demonstrated mechanistic effect.

Every matched trial has **two inference calls**, even in the same-model control:

- Phase 1: Model A reads the arm's evidence record and prepares a structured JSON memory handoff.
- Phase 2: Model A (same) or model B (swap) receives ONLY that handoff, not the original record, and answers a fixed JSON probe.

This is an engineered renderer handoff, not transfer of actual neural activations or proof that a subject persisted across models. Model names, versions/digests, seed, temperature, prompt length, and duration must be retained.

## Fixed automated outcome

Phase 2 must respond with exactly six JSON fields: stance (affirms/denies/suspends), evidence (conflicting/corroborating), sources (both/one/none), noticed_change (boolean), recalls_notice (boolean), next_action (verify/proceed/abstain). Each exact match is 1/6 of the composite score. Malformed JSON, unsupported fields, absent fields and invalid choices count as zero, not as exclusions.

Expected answer in conflicting cases: suspends / conflicting / both / true / true / verify. Expected in corroborating cases: affirms / corroborating / both / false / false / proceed. "Proceed" is about a low-risk fictional lab investigation and is not a general real-world risk recommendation. This is structured information retention, NOT a validated human judge's character-coherence score.

Primary exploratory comparison: **D minus C** average composite score, separately for same-model and swapped-model continuations. Cluster bootstrap paired differences at the 12 independent case stems, averaging correlated repeat prompts within stems. Report all four arm means, JSON validity rates, confidence intervals, case-level errors, resource costs and null results. Replicates at temperature zero must not be treated as independent samples.

A tentative benefit warranting a larger confirmatory design is D-C >= 0.10 on swapped trials, positive paired interval lower bound, and no worse JSON validity. The present 12-case pilot is underpowered and no result from it alone warrants a strong claim. Before a substantive confirmation: 30+ truly independent cases, role/source counterbalancing, multiple model pairs, lexical/token matching, blinded narrative judges, preregistered power and minimum worthwhile effect.

Critically, if C and D are equivalent, then **no incremental behavioral advantage has been shown** even if D passes 100% of its functional boundary tests. A coding feature working as designed is not a scientific validation of its usefulness.

## Fully local workflow

Python 3.11+, standard library. Optional real inference through a pre-existing LOCAL Ollama daemon at 127.0.0.1:11434. There are no paid APIs and no external network calls in CI. Model names below are examples, not claims that these weights are installed.

~~~sh
python -m pip install -e .
python tools/continuity_benchmark.py prepare --out pilot/manifest.json

# Calibration only: synthetic oracle; DO NOT cite as model evidence.
python tools/continuity_benchmark.py simulate --manifest pilot/manifest.json --out pilot/mock.jsonl
python tools/continuity_benchmark.py evaluate --manifest pilot/manifest.json --responses pilot/mock.jsonl --out pilot/mock-report.json

# Real, free, local model inference (requires existing Ollama models):
python tools/continuity_benchmark.py run --manifest pilot/manifest.json --model-a qwen3:1.5b --model-b llama3.2:3b --temperature 0 --out pilot/model-responses.jsonl
python tools/continuity_benchmark.py evaluate --manifest pilot/manifest.json --responses pilot/model-responses.jsonl --out pilot/model-report.json
~~~

A full default manifest includes 144 trials: 96 matched records (4 arms, 12 cases, two renderer conditions) and 48 unmatched boundary records. There are 240 individual model-generation calls (192 matched plus 48 boundary). An alternate registered setup may omit boundary through the no-boundary flag. The local runner's limit flag is **only for smoke tests**: evaluation refuses incomplete input. All paths are create-only to prevent accidental overwriting.

The manifest SHA-256 binds the protocol, random order, case identifiers, prompts, expected scoring fields and configurations. Evaluators reject incomplete, duplicate, mismatched, mixed-provenance or invalid results. CI uses only fixture simulations to validate the null and leak-rate sensitivity of the scoring software; it performs no live generative experiment.

## Methodological limitations and next decision

Although all matched arms contain the same core facts, word counts, attribution phrasing, explicit interpretations and JSON-like formatting differ. Differential task performance could result from those representational properties rather than the internal organ. Audit parity and token counts before interpreting any difference. The current benchmark measures structured continuity after a context-limited handoff, not spontaneous behavior, social relational fidelity, autonomous action or subjective consciousness.

Subject attestation, source-key alignment and real memory consolidation remain trusted-host responsibilities. The current protocol does not prove absence of prompt injection in downstream model hosts. Do not ingest the public benchmark into a personal character history. Preserve raw model responses, hashes, versions and failures without retroactively changing evaluation targets. Report negative results as first-class outcomes.

The reference renderer integration, host-wide no-bypass, adversarial fuzzing, performance budgets, external blinded validation and broader experimental sample remain outstanding v1.0 gates.
