## Failure mechanism (post hoc descriptive inspection)

All 4 final-stage responses by SmolLM2-135M were not parseable as JSON. The model largely copied or paraphrased the incoming contextual history instead of answering in the mandated six-field form. One run exhausted the 128-new-token cap through repetition.

All 4 final-stage responses by SmolLM2-360M were syntactically parseable JSON but **0/4 satisfied the exact schema**. Visible errors included `sources` emitted as arrays rather than one of `both|one|none`, misspelled or modified `noticed_change` / `recalls_notice` keys, and `stance=denies` in cases where the fixed rubric required suspended judgment. These are actual observed model errors, not parser bugs to waive retroactively.

No response was dropped or imputed. The locked v0.9 scorer was not modified after inspection. The paired results remain logged as zero with validity rate zero.

This is a meaningful **feasibility finding**: a six-field structured reporting interface is too demanding for these particular unadapted micro models under the tested zero-shot instructions, so the benchmark cannot resolve downstream continuity differences at this size. That does not invalidate the v0.8 organ's engineering protections.

## Next falsifiable gate, not a retroactive re-score

Retain the raw failures as immutable pilot evidence. Register a separately versioned **format-calibration** study before running new models: test simple, single-field or constrained-answer extraction on the SAME held-out facts with per-field accuracy and format validity reported separately, or run stronger local models capable of the fixed six-field schema. Do not compare the modified format scores to the original v0.9 score as if they were one preregistered experiment.

Only when response validity is adequate should a broader information-parity audit, multi-model swap experiment and independent action-coherence test be used to assess whether the organ adds behavioral value beyond first-person wording.
